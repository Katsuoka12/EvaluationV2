แผนผังการทำงานระบบประเมินผลบุคลากร

1. แผนผังการเข้าสู่ระบบ (Login Flow)

flowchart TD
    A([เริ่มต้น]) --> B[เปิดหน้าเข้าสู่ระบบ]
    B --> C{มี token อยู่แล้วหรือไม่}
    C -- มี --> D[เปลี่ยนไปหน้า Dashboard]
    C -- ไม่มี --> E[กรอก Username และ Password]
    E --> F{ข้อมูลครบหรือไม่}
    F -- ไม่ครบ --> G[แจ้งให้กรอกข้อมูลให้ครบ]
    G --> E
    F -- ครบ --> H[ส่ง POST /api/auth/login]
    H --> I{พบผู้ใช้ในฐานข้อมูลหรือไม่}
    I -- ไม่พบ --> J[แจ้งว่าไม่พบชื่อผู้ใช้]
    J --> E
    I -- พบ --> K{รหัสผ่านถูกต้องหรือไม่}
    K -- ไม่ถูกต้อง --> L[แจ้งว่ารหัสผ่านไม่ถูกต้อง]
    L --> E
    K -- ถูกต้อง --> M[ออก JWT อายุ 7 วัน พร้อม role]
    M --> N[เก็บ token, role และ username ใน cookie]
    N --> O[โหลดข้อมูลโปรไฟล์]
    O --> P[ไปหน้า Dashboard และแสดงเมนูตาม role]
    P --> Q{ผู้ใช้เลือกออกจากระบบหรือไม่}
    Q -- ไม่ --> R[ใช้งานระบบ]
    Q -- ใช่ --> S[ล้าง cookie และข้อมูลโปรไฟล์]
    S --> B

2. กระบวนการของงานบุคลากร / ผู้ดูแลระบบ (Admin)

flowchart TD
    A([Admin เข้าสู่ระบบ]) --> B[Dashboard]
    B --> C[จัดการรอบการประเมิน]
    C --> D[กำหนดชื่อ ช่วงวัน และสถานะรอบ]
    D --> E[บันทึกรอบลงฐานข้อมูล]
    B --> F[จัดการเกณฑ์ KPI]
    F --> G[สร้างหรือแก้ไขเกณฑ์หลัก]
    G --> H[เพิ่มตัวชี้วัดย่อย / ระบุประเภทคะแนนหรือเอกสาร]
    H --> I[บันทึกเกณฑ์และข้อย่อย]
    B --> J[กำหนดเกณฑ์ตามตำแหน่งและบุคลากร]
    J --> K[เลือกบุคลากรและเกณฑ์ KPI]
    K --> L{เลือกอย่างน้อย 1 คนและ 1 เกณฑ์หรือไม่}
    L -- ไม่ --> M[แจ้งให้เลือกข้อมูลให้ครบ]
    M --> K
    L -- ใช่ --> N[บันทึกการผูก user กับ criteria]
    N --> O[ผู้รับการประเมินเห็นเกณฑ์ที่ได้รับมอบหมาย]
    B --> P[แก้ไขโปรไฟล์ของตนเอง]
    O --> Q([จบขั้นตอนเตรียมระบบ])

3. กระบวนการของผู้รับการประเมิน (Staff / User)

flowchart TD
    A([ผู้รับการประเมินเข้าสู่ระบบ]) --> B[Dashboard]
    B --> C[ตรวจสอบ / ปรับปรุงโปรไฟล์และตำแหน่ง]
    B --> D[เปิดแบบประเมินตนเอง]
    D --> E[โหลดรอบประเมิน เกณฑ์ที่ได้รับ และคะแนนเดิม]
    E --> F{พบรอบประเมินหรือไม่}
    F -- ไม่พบ --> G[แจ้งว่าไม่มีรอบที่เปิดใช้งาน]
    F -- พบ --> H{มีรายการประเมินของตนแล้วหรือไม่}
    H -- ไม่มี --> I[สร้างรายการประเมินสถานะกำลังประเมิน]
    H -- มี --> J[เปิดรายการเดิม]
    I --> K[กรอกคะแนนตนเองและข้อมูลหลักฐาน]
    J --> K
    K --> L{เลือกการทำงาน}
    L -- บันทึกร่าง --> M[บันทึกคะแนนและหลักฐาน]
    M --> K
    L -- ส่งผลประเมิน --> N[ยืนยันการส่ง]
    N --> O{ยืนยันหรือไม่}
    O -- ไม่ --> K
    O -- ใช่ --> P[บันทึกคะแนนและเปลี่ยนสถานะเป็น completed]
    P --> Q[แสดงว่าส่งผลประเมินแล้ว]
    Q --> R([สิ้นสุด])

4. กระบวนการของกรรมการผู้ประเมิน (Assessor)

flowchart TD
    A([Assessor เข้าสู่ระบบ]) --> B[Dashboard]
    B --> C[เปิดรายการประเมินบุคลากร]
    C --> D[โหลดรายการและตัวกรองสถานะ / ค้นหาชื่อ]
    D --> E{ต้องสร้างรายการประเมินใหม่หรือไม่}
    E -- ใช่ --> F[เลือกบุคลากร ตำแหน่ง และรอบ]
    F --> G{กรอกข้อมูลครบหรือไม่}
    G -- ไม่ครบ --> F
    G -- ครบ --> H[สร้างรายการสถานะกำลังประเมิน]
    E -- ไม่ --> I[เลือกรายการที่ต้องการตรวจ]
    H --> I
    I --> J[เปิดรายละเอียดและโหลดเกณฑ์กับคะแนน]
    J --> K[กรอกคะแนนผู้ประเมินและข้อเสนอแนะ]
    K --> L{บันทึกหรือส่งผลประเมิน}
    L -- บันทึก --> M[บันทึกคะแนนผู้ประเมิน]
    M --> K
    L -- ส่งผล --> N[บันทึกคะแนนและเปลี่ยนสถานะเป็น completed]
    N --> O[กลับไปดูรายการประเมิน]
    O --> P([สิ้นสุด])

5. ภาพรวมระบบ (System Flow Overview)

flowchart LR
    subgraph U[ผู้ใช้งาน]
      AD[Admin]
      AS[Assessor]
      ST[Staff / ผู้รับการประเมิน]
    end

    subgraph FE[Frontend: Nuxt]
      LG[Login / Register]
      DB[Dashboard และ Profile]
      CFG[หน้าจัดการรอบ เกณฑ์ และมอบหมายเกณฑ์]
      LIST[รายการประเมินบุคลากร]
      SELF[แบบประเมินตนเอง]
      DETAIL[รายละเอียดและให้คะแนนผู้ประเมิน]
    end

    subgraph API[Backend: Express REST API]
      AUTH[Auth API: login / register]
      PROF[Profile API]
      EVAL[Evaluation API]
      JWT[ตรวจสอบ JWT]
    end

    DBMS[(MySQL: users, profiles, periods, criteria, evaluations, scores, mappings)]

    AD --> LG
    AS --> LG
    ST --> LG
    LG --> AUTH
    AUTH --> DBMS
    AUTH -->|JWT + role| DB
    DB --> PROF
    PROF --> JWT
    PROF --> DBMS
    AD --> CFG
    CFG --> EVAL
    AS --> LIST
    LIST --> EVAL
    ST --> SELF
    SELF --> EVAL
    AS --> DETAIL
    DETAIL --> EVAL
    EVAL --> JWT
    JWT --> DBMS
    DBMS -->|ข้อมูลและผลลัพธ์| EVAL
    EVAL -->|JSON| CFG
    EVAL -->|JSON| LIST
    EVAL -->|JSON| SELF
    EVAL -->|JSON| DETAIL
